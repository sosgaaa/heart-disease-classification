\section*{Introduction}
We explore three ML algorithms for classification and clustering: K-Nearest Neighbors (KNN), K-Means clustering, and Logistic Regression. \newline 
$\bullet$ \textbf{K-Nearest Neighbors (KNN)}: Non-parametric algorithm where predictions are made based on majority class among 'k' closest neighbors. \newline
$\bullet$ \textbf{K-Means clustering}: Unsupervised learning algorithm partitioning data into 'k' distinct clusters.\newline
$\bullet$ \textbf{Logistic Regression}: Classification algorithm modeling class probability using a logistic function. \newline These models were implemented and evaluated on our dataset to compare their effectiveness, computational efficiency, and sensitivity to hyperparameters and preprocessing techniques in order to find the best performing model for the heart disease dataset.
\vspace{-0.4cm}
\section*{Methodology}
\subsection*{Data Preparation}
The dataset is made out of 13 features and 297 samples. Given the three models' sensitivity to feature scaling and irrelevant features, significant preprocessing was applied to the training data before fitting the model (for more details see figure \ref{fig:raw_data}, \ref{fig:partial_prep} and \ref{fig:full_prep} in \ref{app:data_prep}). First, the data was normalized using the mean and standard deviation calculated from the training set. To mitigate the impact of potential outliers, values were then clipped based on the interquartile range (IQR). Following clipping, MinMax scaling was applied to bring all features into the [0, 1] range (all was done after searching actual field used methods). Finally, recognizing that not all features contribute equally, we employed a feature selection technique based on variance since non-variant features don't contribute to the model's performance. Only the top 10 features exhibiting the highest variance in the preprocessed training data were retained for KNN. For KMeans, we used the top 7 features after manual inspection showing a really good accuracy in the validation set as shown in \textbf{Figure 1}. See Appendix \ref{app:data_prep} for detailed comparisons of model performance with different levels of data preprocessing. For logistic regression, we kept all features after normalization and added a bias term to each sample, as the model can automatically learn feature importance through its weights. This multi-step preprocessing aimed to standardize feature contributions, reduce noise, and improve computational efficiency and model performance. \\[5pt]

\subsection*{Models Implementation}
\textbf{KNN}: Our implementation uses Euclidean distance with inverse distance weighting for predictions. This weighting gives closer neighbors stronger influence, refining decision boundaries. \\
\textbf{K-Means}: We adapted this unsupervised algorithm for classification by mapping clusters to the most frequent class label among members. Centroids were initialized by randomly selecting k data points, then iteratively updated until convergence after random initialization using the seed 42 giving the best mean results over time. \\
\textbf{Logistic Regression}: Our implementation utilizes the softmax function for multi-class probability calculation and employs gradient descent for optimizing the weights. It incorporates L2 regularization (controlled by the `reg` hyperparameter) to prevent overfitting and assumes a bias term has been added to the input data during preprocessing, as reflected in the weight matrix dimensions.\\

\section*{Experiments and Results}
\subsection*{Validation Strategy}
Before hyperparameter tuning, trial and error was necessary using validation sets. We first determined the optimal training-validation split ratio to ensure reliable model evaluation. We experimented with multiple split percentages (15\%, 18\%, 20\%, 22\%, and 25\%) and evaluated model performance for each configuration in the validation set. \textbf{Figures 2} and \textbf{3} shows the accuracy results across different validation split sizes for the most optimal K during hold out validation. Analysis revealed that a 20\% validation split provided the best balance between having sufficient training data and a representative validation set with good performance. Since the objective was to first maximize the validation set accuracy, we chose 20\% as the final validation split size. After choosing the best split size, we found that hold-out validation gave us k = 7 (\textbf{68.571\%}) for KNN and k = 34 (\textbf{71.154\%}) for KMeans in order to have a good balance between the two models and not overfit. \\

\subsection*{Hyperparameter Tuning}
\textbf{KNN}: Since hold out validation gave us a good estimate of the model's performance, we were able to make a more accurate choice of k by using 5-fold stratified cross-validation to determine the optimal k as shown in \textbf{Figure 5}. Testing odd values from 1-30 (since k must be odd and must be small enough to not overfit), we found k = 3, 5, 7 yielded the lowest error rate. With this, we were able to match what we found in the hold-out validation and properly choose the best k. Finally, k=7, was chosen as the final model using the elbow method, maximizing the validation set accuracy and still giving a good performance during the training. The results are shown in \textbf{Figure 5} and proved in \textbf{Figure 6}, giving us an accuracy of \textbf{68.571\%} during hold out validation.

\textbf{K-Means}: Grid search across different cluster counts (5-50) and feature selections revealed optimal performance with k=34 clusters. Performance stabilized after approximately 35 clusters and started overfitting. We had first started by choosing k = 5 since it was the number of classes, but we quickly realized that this was not the best choice. Since K-Means clustering is unsupervised and classes may have complex, non-spherical distributions, using more clusters (k > 5) allows the algorithm to better capture these intra-class structures, potentially leading to improved classification performance after assigning cluster labels. Indeed, the model was not overfitting until k=34, giving us a performance of \textbf{71.154\%}. The results are shown in \textbf{Figure 7}. \textbf{Logistic Regression}: We developed a comprehensive approach to hyperparameter optimization by analyzing three key performance surfaces: mean cross-validation accuracy, 5 fold cross validation set accuracy, and their combined average. By maximizing this combined metric, we identified lr=$10^{-1}$ and 500 iterations as optimal parameters, ensuring good performance on both validation sets simultaneously, giving us a final accuracy for the validation set of \textbf{65.714\%} and a F1 score of \textbf{0.44}.

\section*{Conclusion/Discussions}
Our experiments highlighted the critical impact of data preprocessing; a comprehensive pipeline involving normalization, outlier clipping, MinMax scaling, and variance-based feature selection significantly boosted performance across models. However, the dataset presents significant challenges. The class distribution is notably imbalanced (training: [128, 41, 30, 30, 8], test: [32, 13, 5, 5, 5]), particularly for the least frequent class (label 4). This imbalance likely hampered the models' ability to generalize, especially for minority classes, potentially impacting metrics like the macro F1 score which would be way more important in this setup. Furthermore, the relatively small sample size (297 samples) increases sensitivity to noise and the risk of overfitting, making robust validation techniques like cross-validation essential, although not foolproof.

Future work could involve employing techniques specifically designed for imbalanced data. Exploring alternative feature selection methods or more complex models might yield further improvements, contingent on potentially acquiring more data. Ultimately, while KNN and LogReg showed promise on this dataset, their performance is intrinsically linked to the rigorous preprocessing pipeline developed and constrained by the inherent limitations of the dataset's size and balance while KMeans was not able to give us a really good performance on the test set most likely because of the predominance of the class 0.
